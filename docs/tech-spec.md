# Jipsee 기술 명세

Oct 18, 2026 · @윤상준

관련 문서: [Jipsee 기획서 (PRD)](./prd.md)

## 1. 구조

&#91;embedded content: 데이터 흐름: 수집, 매칭, 저장, 조회\]

| 항목 | 내용                                                                         |
| ---- | ---------------------------------------------------------------------------- |
| 연결 | 실거래와 건축물대장은 건물 매칭으로 연결해 저장. 법령은 검색용으로 따로 저장 |
| 조회 | 화면과 챗봇이 같은 조회 함수 사용. 응답 변환만 분리                          |
| 갱신 | 최초 일괄 적재 후 변경분만 반영                                              |
| 표시 | 계산, 통계 없이 저장한 데이터를 그대로 제공. 공시가격은 공시가격알리미 링크  |

## 2. 스택

### 백엔드

| 영역             | 선택                                                         |
| ---------------- | ------------------------------------------------------------ |
| 언어, 프레임워크 | Java 25 (LTS), Spring Boot 4.1                               |
| 데이터 접근      | JPA. 대량 적재, 공간 검색은 JdbcTemplate                     |
| 수집 작업        | Spring Batch 6 + spring-boot-starter-batch-jdbc              |
| 일정 실행        | 스케줄러 + ShedLock                                          |
| DB 마이그레이션  | Flyway + flyway-mysql                                        |
| 로그인           | OAuth2 Client (구글, 카카오, 네이버), Spring Session + Redis |
| 요청 제한        | Bucket4j + Redis                                             |
| 동시 연결        | Spring MVC + 가상 스레드                                     |
| 챗봇             | Spring AI 2.0, SSE                                           |
| 봇 차단          | Cloudflare Turnstile                                         |

### 데이터

| 영역      | 선택                                                      |
| --------- | --------------------------------------------------------- |
| DB        | MySQL 8.4 LTS                                             |
| 검색      | FULLTEXT ngram (주소, 건물명, 법령)                       |
| 반경 검색 | 공간 인덱스. MBRContains 후 ST_Distance_Sphere (long-lat) |
| 공유 상태 | Redis 8.2 (appendonly)                                    |

### 프론트

| 영역       | 선택                   |
| ---------- | ---------------------- |
| 프레임워크 | Next.js 16, TypeScript |

### 인프라

| 영역             | 선택                                     |
| ---------------- | ---------------------------------------- |
| 서버             | Oracle A1 (2 OCPU, 12GB, 오사카), Ubuntu |
| 실행             | Docker Compose                           |
| 앞단             | Cloudflare, nginx + certbot              |
| CI/CD            | GitHub Actions                           |
| 로깅 및 모니터링 | fluent-bit, Loki, Prometheus, Grafana    |
| 에러 추적        | Sentry                                   |
| 배포             | blue/green (nginx upstream 전환)         |

## 3. 데이터 매칭

| 단계         | 규칙                                                                    |
| ------------ | ----------------------------------------------------------------------- |
| 1. 후보 조회 | 지번으로 건축물대장 조회. 지번 없으면 법정동 + 건물명 + 건축년도 (추정) |
| 2. 연도 대조 | 건축년도와 사용승인일 불일치 시 이전 건물 거래로 분리                   |
| 3. 이름 대조 | 후보 여러 개면 정규화 건물명 유사도로 선택                              |
| 4. 결과      | 확정, 추정, 이전 건물, 실패                                             |
| 건물 ID      | 자체 ID. 외부 키는 매핑 테이블                                          |
| 품질         | 시군구별 표본 수동 검수                                                 |

## 4. 데이터

### 출처

| 데이터              | 출처                      | 갱신           | 이용 조건                    |
| ------------------- | ------------------------- | -------------- | ---------------------------- |
| 연립다세대 전월세   | 공공데이터포털 API        | 매일           | 이용허락범위 미확인          |
| 연립다세대 매매     | 공공데이터포털 API        | 매일           | 이용허락범위 미확인          |
| 건축물대장 (표제부) | 건축HUB 파일              | 매월           | 제한 없음                    |
| 좌표                | 지오코딩 API              | 실거래 수집 시 | 결과 저장 허용 서비스만 사용 |
| 법령, 판례          | 법제처 API (서버 IP 등록) | 개정 시        | 저작권 보호 대상 아님        |

### 저장 규칙

| 항목       | 규칙                                                                                                                  |
| ---------- | --------------------------------------------------------------------------------------------------------------------- |
| 원본 보존  | 응답 필드 그대로 저장. 금액(콤마 문자열, 만원)만 숫자로 변환                                                          |
| 중복       | 거래 ID 없음. 시군구 + 계약 월 단위로 교체                                                                            |
| 해제, 갱신 | 원본 필드 그대로 표시                                                                                                 |
| 수집 한도  | 오류 22(일일 한도) 시 다음 날 이어서 수집                                                                             |
| 건축물대장 | 최초 적재는 로컬 LOAD DATA 후 덤프 복원. 이후 매월 변동분 반영                                                        |
| 적재 범위  | 연립 또는 다세대 동이 있는 필지의 동 전부. 총괄표제부 제외. 주용도와 대장 종류는 걸러내는 용도로만 쓰고 저장하지 않음 |

### 제약

| 항목        | 내용                              |
| ----------- | --------------------------------- |
| 공개 지연   | 최근 1\~2개월 거래는 계속 늘어남  |
| 누락        | 확정일자 없는 계약은 빠질 수 있음 |
| 조회 단위   | 시군구 + 계약 월                  |
| 동, 호 없음 | 건물, 면적 단위 비교만 가능       |
| 제공 불가   | 등기부, 임대인 정보               |

## 5. 챗봇

### 처리 순서

1. 앞단 검사: 로그인, 봇 차단, 요청 제한. 실패 시 거부 응답
2. 주제 제한: 범위 밖이면 안내 문구로 끝. 여기까지 LLM 비용 없음
3. LLM 호출: 도구로 건물 조회, 법령 검색
4. 스트리밍: 출처, 기준일과 함께 응답. nginx 버퍼링 끔, 15초마다 heartbeat

### 답변 규칙

| 항목      | 규칙                                      |
| --------- | ----------------------------------------- |
| 근거      | 도구 결과로만 답변. 계산, 추정 금지       |
| 표현      | 판단 문구 금지 (적정, 위험 등)            |
| 출처      | 출처와 기준일 표시                        |
| 법령      | 일반 정보만. 개별 사건은 전문가 상담 안내 |
| 공시가격  | 공시가격알리미 링크                       |
| 평가 세트 | 50\~100문항. 통과율 미달 시 배포 중단     |
