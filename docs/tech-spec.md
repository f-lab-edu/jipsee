# Jipsee 기술 명세

Oct 18, 2026 / @윤상준

관련 문서: [Jipsee 기획서 (PRD)](./prd.md)

## 1. 스택

### 백엔드

| 영역             | 선택                                                                                                                                                                   |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 언어, 프레임워크 | Java 25 (LTS), Spring Boot 4.1                                                                                                                                         |
| 데이터 접근      | 배치가 공공데이터를 적재하는 테이블(`rent_deal`, `sale_deal`, `deal_group`, `collect_status`)은 읽기와 쓰기 모두 JdbcTemplate 사용. 적재 테이블은 `id`가 `auto_increment`라 JPA에서는 insert 배치가 꺼지고, 교체 단위 삭제와 삽입을 SQL로 바로 쓰는 편이 단순하기 때문 |
| 수집 작업        | Spring Batch 6 + spring-boot-starter-batch-jdbc                                                                                                                        |
| 스케줄 실행      | Jenkins가 Job마다 컨테이너를 실행함(`BatchJobRunner`가 Job 하나를 실행하고 종료 코드를 반환함)                                                                                                                                                            |
| 중복 실행 방지   | 일일 Job은 수집 날짜를, 초기 적재 Job은 끝 월을 Job 파라미터로 넘김. 같은 파라미터의 Job이 완료됐거나 실행 중이면 Spring Batch가 실행을 거부하고, 실패한 Job은 같은 파라미터로 다시 시작함 (blue/green 전환 중 컨테이너 2개가 함께 실행되는 경우 대비) |
| 동시 연결        | Spring MVC + 가상 스레드                                                                                                                                               |

### 데이터베이스

| 영역      | 선택                                                            |
| --------- | --------------------------------------------------------------- |
| DB        | MySQL 8.4 LTS                                                   |
| 시각      | DATETIME 타입에 KST로 저장함 (JVM은 Asia/Seoul, MySQL은 +09:00) |
| 검색      | 요약 테이블 `deal_group`의 `name`에 FULLTEXT ngram 사용. 일일 수집 뒤 배치 Step이 `deal_group`을 갱신하므로 검색 결과는 최대 하루 늦게 반영됨 |

### 프론트엔드

| 영역       | 선택                                |
| ---------- | ----------------------------------- |
| 프레임워크 | Next.js 16 (App Router), TypeScript |
| UI         | Seed Design                         |
| 구조       | FSD                                 |
| 린트, 포맷 | Biome                               |

### 인프라

| 영역          | 선택                                                                           |
| ------------- | ------------------------------------------------------------------------------ |
| 서버          | Oracle A1 (4 OCPU, 24GB, 오사카), Ubuntu                                       |
| 실행          | Docker Compose                                                                 |
| 리버스 프록시 | nginx + certbot                                                                |
| CI/CD         | GitHub Actions                                                                 |
| 로그          | 앱 로그 파일(`/var/log/jipsee/app/jipsee.log`, 하루 단위, 7일 보관)            |
| 로그 수집     | fluent-bit, Loki. fluent-bit이 앱 로그를 Loki로 전송하고 Loki가 유일한 로그 저장소로 90일 보관함 |
| 모니터링      | Prometheus, Grafana. 앱 메트릭을 노출하고, 배치 대시보드는 Jenkins Prometheus 플러그인 메트릭을 사용하며, 배치 실패 알림은 Jenkinsfile이 보내는 웹훅임 |
| 배포          | blue/green (nginx upstream을 전환함)                                           |
| 백업          | mysqldump로 매일 1회 백업해 Oracle Object Storage에 저장하고 최근 7개만 보관함 |

## 2. 데이터

### 출처

| 연립다세대 매매     | 공공데이터포털 API                   | 매일               | 이용허락범위 미확인                  |

### 저장 규칙

| 항목       | 규칙                                                                                                                                                                                                                                |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 원본 보존  | 필드는 원본 값 그대로 저장하되, 금액(숫자 또는 콤마가 포함된 문자열, 단위 만원)만 숫자로 변환하고, 화면과 검색에 쓰지 않는 필드는 저장하지 않음                                                                                               |
| 교체 단위  | 원본에 거래 ID가 없어 행 단위로 수정할 수 없음. API 조회 단위인 시군구와 계약 월(LAWD_CD, DEAL_YMD, 예: 11110, 202509)의 기존 행을 모두 지우고 새로 받은 행을 넣음                                                                  |
| 재수집     | 매일 최근 6개월분을 다시 수집함. 매매 계약이 취소(해제)되면 원래 거래 행에 해제 표시가 나중에 붙으며, 표본에서는 최대 5개월 뒤에 붙었음                                                                                             |
| 수집 순서  | (시군구, 월) 하나씩 API 조회, 교체 조건 확인, 교체를 끝낸 뒤 다음 (시군구, 월)로 넘어감. 동시에 여러 개를 수집하지 않음                                                                                                             |
| 트랜잭션   | (시군구, 월)마다 기존 행 삭제와 새 행 삽입을 한 트랜잭션으로 묶음. 삽입이 실패하면 삭제도 취소됨                                                                                                                                    |
| 교체 조건  | 응답이 불완전하면 기존 행을 지우지 않음. 마지막 페이지까지 받고, resultCode가 000(정상)이고, 받은 건수가 totalCount(API가 알려 준 전체 건수)와 같을 때만 교체함                                                                     |
| 0건 응답   | 기존 행이 있는데 0건이 오면 API 오류로 보고 교체하지 않으며 로그를 남김                                                                                                                                                             |
| 수집 한도  | 오류 22(일일 한도)가 발생하면 Step이 실패함. 초기 적재는 다음 날 같은 파라미터로 Job을 시작하면 마지막으로 커밋한 (시군구, 월)부터 이어서 수집하고, 일일 수집은 Jenkins가 같은 날 다시 시도하지 않고 다음 날 최근 6개월을 처음부터 다시 수집함                                                                                                                                                                                 |

### 제약

원본에 동과 호 정보가 없어 거래 묶음(시군구 코드, 법정동명, 지번)과 면적 단위로만 비교 가능

## 3. 검색

### 건물 검색

| 항목           | 규칙                                                                                                                                         |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 검색 결과 단위 | 시군구 코드, 법정동명, 지번이 같은 거래를 거래 묶음 1건으로 반환. 묶음은 `deal_group`에 저장하며 일일 수집 뒤 배치 Step이 갱신함           |
| 묶음 id        | `{sigungu_code}-{legal_dong_name}-{lot_number}` 문자열 (예: `11440-망원동-123-4`)                                                            |
| 검색어 길이    | 앞뒤 공백을 제외한 검색어 전체가 2글자 이상                                                                                                  |
| 단어 분류      | 앱이 법정동 사전(`bjd.csv`)으로 검색어를 단어별로 분류                                                                                     |
| 지번 단어      | `lot_number` REGEXP `(^\|[^0-9-])<단어>([^0-9]\|$)`로 검색. 지번 뒤에 숫자가 이어지면 제외 (12 검색 시 123은 제외, 12-5는 포함)            |
| 시군구, 법정동 | 사전의 시군구명 또는 읍면동명과 전체가 일치하면 `sigungu_code`, `legal_dong_name` 조건으로 검색                                            |
| 그 밖의 단어   | 2글자 이상이면 `house_name` FULLTEXT ngram으로, 1글자면 `house_name` LIKE로 검색                                                           |
| 조건 결합      | 모든 단어의 조건을 AND로 결합                                                                                                              |
| 후보 행 상한   | `rent_deal`, `sale_deal` 각각에서 일치한 행을 관련도순으로 최대 5,000행까지 사용                                                           |
| 묶기, 페이지   | 일치한 행만 묶음 키로 묶고, 20건 단위로 조회하며 응답에 `hasNext` 포함                                                                   |
| 묶음 이름      | 결과의 묶음 이름은 일치한 행이 아니라 묶음의 전체 거래로 정함. 계약일이 가장 늦은 거래의 `house_name`이며 `docs/erd.md`의 묶음 이름과 같은 규칙 |
| 인덱스         | `rent_deal`, `sale_deal`에 `(sigungu_code, legal_dong_name, lot_number, deal_date)`와 `house_name` FULLTEXT ngram 추가. 기존 `(sigungu_code, deal_date)`는 재수집의 삭제 대상 조회에 유지 |

### 건물 상세

| 항목      | 규칙                                                                                  |
| --------- | ------------------------------------------------------------------------------------- |
| 거래 이력 | 묶음 키가 같은 `rent_deal`, `sale_deal` 거래 전체를 계약일 최신순으로 반환          |
| 오류      | id 형식이 맞지 않거나 묶음 키가 같은 거래가 없으면 404 `BUILDING_NOT_FOUND` 반환  |

### 주변 거래

| 항목 | 규칙                                                                                                                               |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 범위 | 묶음 id의 시군구 코드와 법정동명이 같은 `rent_deal` 거래                                                                           |
| 페이지 | 20건 단위로 조회하고 응답에 `hasNext`와 `totalCount` 포함. `totalCount`는 같은 조건의 `COUNT(*)`                              |
