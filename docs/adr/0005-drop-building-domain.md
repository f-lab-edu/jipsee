# 0005. 건물 도메인 제외와 지번 자연 키

## 상태

- 채택 (2026-11-21)

## 맥락

- 프로젝트 목표는 배치, 인프라와 운영, 캐시와 트래픽, LLM 같은 기술 학습
  - 챗봇은 2단계에서 진행
- 건축물대장 수집과 건물 매칭의 범위가 커서 기술 학습에 쓸 시간 부족
- 운영 데이터 실측 결과, 시군구 코드, 법정동 이름, 지번이 모두 같은 거래 중 99.40%는 건물 이름이 하나뿐이므로 건축물대장이 필수는 아니라고 판단
  - 원래는 건축물대장 기반으로 거래에 해당하는 건물을 찾아서 세부 정보를 제공하려고 했음

## 결정

### 건축물대장 수집과 건물 매칭 제외

- 1단계에서 건축물대장 수집과 건물 매칭을 진행하지 않음

### 지번 단위 거래를 건물 식별자로 사용

- `(sigungu_code, legal_dong_name, lot_number)`가 같은 거래를 하나의 건물로 취급
- 건물 id는 `{sigungu_code}-{legal_dong_name}-{lot_number}` 형식의 문자열 사용

### 건물 이름과 지번이 null인 거래

- 건물 이름은 가장 최근 거래의 `house_name`으로 사용, 해당 값이 없으면 지번 주소를 대신 사용
  - 2단계에서 건축물대장 기반으로 정확한 이름 파악 예정
- `lot_number`가 null인 거래는 건물에서 제외하고 주변 거래에만 포함

## 대안

- 건물 테이블 저장: 새 테이블과 배치 Step이 필요하여 채택하지 않음. 스코프가 너무 커짐. 이후 검색 성능 문제로 0010에서 채택
- `building_parcel_id` 식별: 건물 도메인을 제외하므로 사용할 수 없어 채택하지 않음

## 결과

- 공식 건물명, 건축물대장 정보, 한 필지 안의 여러 건물 구분은 미제공
- 이름이 여러 개인 건물은 최근 거래의 이름 하나만 표시
- id 형식이 맞지 않거나 해당 거래가 없으면 404 `BUILDING_NOT_FOUND`로 응답
